# 三国竞拍：多桌锦标赛 Demo 设计文档

> 项目代号：**sanBid**
> 版本：v0.1（demo 起草）
> 文档目的：在动手写代码前对齐基础规则与系统边界

---

## 1. 项目愿景

一个以三国为皮肤、参考《竞拍之王》**仓库盲盒 + 明码递降阈值**竞拍机制、并融合德州扑克 MTT（多桌锦标赛）盲注递增/重购结构的单机演示游戏。

- 形态：**纯前端**（HTML + TypeScript/JavaScript），浏览器即开即玩
- 玩家数：1 人 + 3 AI（同桌）
- 主交付模式：**多桌锦标赛（MTT）**，常规拍卖作为 MTT 内的子场次出现
- 后续可扩展：联网多人（架构层预留消息抽象）

---

## 2. 核心机制总览

### 2.1 双货币体系

| 名称 | 角色 | 在 demo 中的来源 |
|---|---|---|
| **军资（主要货币）** | 用于"买入"锦标赛、re-buy / add-on，账户级钱包 | 玩家初始持有，演示阶段给定固定数额 |
| **筹码（次要货币）** | 桌内出价、押注的实际单位 | 通过买入兑换；锦标赛结束时不可换回 |

> 类比：军资 = 真金白银；筹码 = 麻将馆的塑料筹码。

### 2.2 三国皮肤化

- 玩家 = 武将（曹操、刘备、孙权、诸葛亮、周瑜、关羽…）
- 拍品 = 三国典籍/兵器/异宝（玉玺、青釭剑、赤兔马、孟德新书、铜雀台模型……）
- 规则**完全不依赖三国设定**——仅文案/立绘/物品名替换

## 3. 子场次：仓库竞拍（在 MTT 中作为一手"牌"）

### 3.1 场次结构

- 一场常规赛 = 拍 **1 个仓库（盲盒）**
- 一个仓库 = 装着 30~60 件藏品的 **10×20 网格地图**
- 仓库的"真实总值" = 内部所有藏品 `trueValue` 之和
- 拍卖采用"明码 + 阈值递降"机制，**最多 5 轮**报价，可能在任意一轮提前成交
- 中标者获得仓库内**全部藏品**

> 这是与原版"装着未知物品的盲盒"完全对应的玩法——玩家拍的不是单件物品，而是整个仓库的所有权。

### 3.2 仓库结构

#### 网格规格

- 尺寸：**10 列 × 20 行 = 200 格**
- 装载率：**30~60%**（30~60 件藏品塞进去后的覆盖率）
- 排布原则：**自顶向下密集堆放**——藏品集中在前 12~15 行，下半部空旷（视觉上呈"塔顶满载、塔底空旷"的金字塔式重心）

#### 藏品形状

- 从 **1×1** 到 **4×4**
- 含极端形状：**1×6 / 6×1**
- 形状决定占地面积；与价值有正相关但非严格挂钩

#### 6 档稀有度（颜色递增：白→红）

| 档位 | 中文名 | 颜色 | 价值带（筹码） | 单仓典型数量 |
|---|---|---|---|---|
| 1 | 普通 | 白 `#e0d8c8` | 30~100 | 12~18 |
| 2 | 优良 | 绿 `#5cb85c` | 80~180 | 6~10 |
| 3 | 稀有 | 蓝 `#4a8eb8` | 180~350 | 4~7 |
| 4 | 史诗 | 紫 `#a855c7` | 350~550 | 2~4 |
| 5 | 传说 | 金 `#f4c97a` | 550~900 | 1~3 |
| 6 | 神话 | 红 `#e85050` | 900~1200 | 0~1 |

> 价值带相邻档**轻微重叠**（如优良 80~180 与稀有 180~350 共享 180）——同稀有度的藏品价值有波动，避免"知品质=知价值"的退化。

#### 藏品类别

- 6 类：**兵器 / 典籍 / 异宝 / 战马 / 礼器 / 文房**
- 类别**不用颜色编码**（颜色独占给稀有度）
- 类别识别：图标字符（剑/书/玉/马/符/墨）+ 详情面板文字

**视觉参考**：[mockups/warehouse.html](mockups/warehouse.html)

### 3.3 入场费（大盲注）

- **每个仓库开拍前**，桌上每位玩家从筹码中扣一笔"入场费"作为本仓大盲注
- 入场费在常规赛中固定；在 MTT 中等于**当前盲注档位**（见 §5.2）
- 不参与本仓则跳过（视为永远报 0），但仍要付入场费
- **意义**：报价是"誓言"不是即时扣款，必须用入场费给"瞎报"上一道成本

### 3.4 阈值递降成交机制（核心）

每个仓库的拍卖按下列流程推进，**任何一轮达成阈值即立即成交**：

```
准备阶段：扣入场费 → 仓库封缄展示（所有格子未知）
        → 触发开局技能（§6.3）→ 生成 R1 公共信息（§3.6）

第 R 轮：
  1. 玩家阅读本轮公共信息 + 自己的揭示集
  2. 4 名玩家同时提交本轮报价（密封式）
  3. 全部报价依次揭露（明码 + 顺序揭露动画 + 1st 高亮）
  4. 计算 1st、2nd 报价
  5. 若 1st ≥ 2nd × ThresholdMultiplier(R) → 本仓成交（结束）
     否则 → 触发各玩家"出价后"技能（§6.3）→ 生成 R+1 公共信息（§3.6）
          → 进入第 R+1 轮（若已是末轮则按"任意更高即成交"判定）
```

#### 阈值表

| 轮次 R | 阈值倍率 | 含义 |
|---|---|---|
| 1 | **× 2.0** | 1st 必须是 2nd 的 200%（差 1 倍）才能直接拿下 |
| 2 | **× 1.6** | 60% 溢价 |
| 3 | **× 1.3** | 30% 溢价 |
| 4 | **× 1.1** | 10% 溢价 |
| 5 | **× 1.0+** | 任何严格高于 2nd 的报价都成交 |

> 设计直觉：早期阈值高 → 想"一击拿下"成本极大；阈值随轮次降低 → 信息越透明（含技能侦察的累积），成交门槛越宽松。

#### 边界情况裁决

- **末轮（第 5 轮）1st = 2nd 并列最高** → 在并列的最高报价者中**随机选一名**中标
- **某轮全员都报 0（全"过"）** → 直接**流拍**，本仓作废，进入下一仓
- **入场费归向** → **沉没掉**（即从玩家筹码中扣除后不进入任何奖池，纯成本）

### 3.5 信息披露：仓库侦察（取代旧版"线索文字"）

信息披露分**两条独立通道**：

#### A. 私密通道：竞拍人技能（仅自己可见）
- 开局时仓库完全封缄，所有藏品未知（[warehouse.html](mockups/warehouse.html) Tab ①）
- 玩家**每次出价后**（且本仓未成交时），自己持有的竞拍人技能触发
- 揭示的信息**仅技能拥有者可见**——这是技能价值的核心
- 4 种侦察状态分别对应：
  - **未知** → Tab ①（开局）
  - **品质已揭示** → Tab ②（左上格亮色点，泄露品质 + 左上位置）
  - **轮廓已揭示** → Tab ③（占位染色，泄露形状 + 位置）
  - **全部揭示** → Tab ④（结算视图 / 司马懿 R4 触发后他自己看到）

详细技能定义见 §6.3。

#### B. 公共通道：每轮公共信息（所有玩家可见）
见 §3.6。

### 3.6 公共信息（每轮）

**每轮开始时（含 R1）**，系统生成一条公共信息，所有玩家可见、AI 估值时也使用。

#### 公共信息类型（4 种，每轮随机抽一种）

| Kind | 内容示例 | 信息强度 |
|---|---|---|
| `reveal-item` | "「青釭剑」（兵器・史诗・2×3）位于第 1 行第 8 列，价值 510 筹码"。该 itemId 进入 `state.publicReveals` | 强（精确 1 件） |
| `rarity-avg` | "本仓【紫色】藏品共 3 件，平均价值 420 筹码"（**仅一档稀有度**） | 中 |
| `rarity-count` | "本仓【紫色】藏品共 3 件"（**仅一档稀有度**，且不含数量） | 弱 |
| `total-area` | "藏品总占地 110 / 200 格（装载率 55%）" | 最弱 |

#### 设计原则

- **不直接泄露红色（神话）藏品数量** —— 神话单件 1100 筹码影响估值过大；`rarity-avg` 与 `rarity-count` 候选档位 **排除红色**
- **一次只揭单档稀有度** —— 不公开整张分布表（避免一次到位推算总值）
- **4 种类型随机轮换** —— 不可预测下一轮会泄露什么 → 保持博弈空间
- **历史累积可见** —— 单局后续轮次中，之前所有轮的公共信息**不会消失**，UI 上以"最新醒目 / 历史淡化"叠放显示，玩家可综合判断（例：R1 已知优良 5 件平均 130，R3 又揭出某件传说 880，玩家可推算除剩余未知部分外的总值下限）
- **不重复**：每"信号槽"在 5 轮内只能用一次：
  - `reveal-item`：每件藏品只能被揭一次（已通过 `state.publicReveals` 实现）
  - `rarity-avg` / `rarity-count`：**同档稀有度共享一个槽位**——一旦某档（如优良）被任意一种揭过，本局不再为该档出 avg 或 count
  - `total-area`：全局只能出一次
  - 兜底：若所有信号槽用尽（5 轮内极少见），输出"本轮无新情报"
- AI 估值（§6.2）将公共揭示的藏品视为"精确已知"，未公共揭示的仍按自己技能/先验估算

> 旧版曾设有 `has-mythic`（公开是否含神话）与 `rarity-counts`（公开 6 档分布表），均因信息过强被移除。

### 3.7 出价规则

- 每位玩家**每轮**只能提交一个报价（即对**整个仓库**的出价）
- **不限制**报价与上轮的关系：可加可保持可降（降价基本无意义）
- 报价必须 ≤ 玩家当前持有筹码（中标后才扣钱，但不能报"自己付不起"的价）
- 弃权选项：本轮可选"过"（视作报价 = 0，不参与本轮成交判定）

### 3.8 中标结算

- 中标者**支付报价金额**，获得仓库内**全部藏品**
- 仓库藏品在场末按 `sum(trueValue) × 1.0` 全额回收为筹码（"低于真实总值中标"才赚，"高于真实总值中标"必亏）
- **未中标者不需为报价付费**——报价是誓言不是抵押。但已支付的入场费不退
- **场末胜利条件**：剩余筹码（含未花掉 + 卖出仓库的回收）最多者胜
  - "不买"也是策略：技能侦察不充分时可全员低报，把仓库拖到末轮便宜成交

## 4. 押注玩法（变动 1）

### 4.1 玩法描述

**每一轮**报价时，玩家**可选**额外下一笔押注，押"**仓库真实总值** 落在 [本轮自己报价 ×0.9, 本轮自己报价 ×1.1] 区间内"。

> 注意：基准是**仓库真实总值**（仓内所有藏品价值之和），不是中标价——这是盲押对整仓的估价能力。

### 4.2 结算规则（重要）

- **本仓最终成交后才结算**所有押注（无论谁中标）
- **关键约束**：押注**只对成交那一轮的报价**生效。如果本仓在第 R 轮成交：
  - 在第 R 轮下的押注 → 按第 R 轮自己的报价 ±10% 判定
  - 在第 1..R-1 轮（未成交的轮次）下的押注 → **直接退还押注金**（不胜不负）
- 命中：押注金 × 该轮返利倍率 返还
- 未命中：押注金没收

### 4.3 押注返利倍率（逐轮递减）

随着轮数推进，玩家可见信息越多，押对越容易，因此返利逐轮降低：

| 轮次 R | 返利倍率 |
|---|---|
| 1 | **× 4.0** |
| 2 | **× 3.5** |
| 3 | **× 3.0** |
| 4 | **× 2.5** |
| 5 | **× 2.0** |

> 设计意图：第 1 轮的盲押是"真信心"，奖励高；第 5 轮的押注几乎是公开估价，奖励低。

### 4.4 押注额（固定 = 5× 入场费）

- 押注金 **固定为 `state.entryFee × 5`**——不可自定金额
  - 例：入场费 100 → 押注金恒为 500
  - 例：MTT 中盲注涨到 400 → 押注金恒为 2000
- 这给玩家一个简单决策模型：要么押要么不押，规则数字干净
- UI 上以"押 ±10%（押注金 500 = 5× 入场费）"的形式呈现
- 安全约束：若 `entryFee × 5 > 玩家筹码 × 50%`（极少数情况，如玩家筹码已极低），则该轮不能押注

### 4.5 设计意图

- 给精准估价的玩家一条"非中标盈利"通道
- 早押的高返利激励玩家"真信心"，晚押的低返利避免"白嫖信息"
- 平衡"装弱不出价"的纯保守策略——不参与就拿不到额外收益

## 5. 多桌锦标赛 MTT（变动 2 + 主交付模式）

### 5.1 赛制结构

- **赛事开始**：所有玩家用军资买入，得到等额筹码
  - 例：初始入场费 = 100 军资 → 换 1000 筹码（兑换比 1:10）
- **同时开多桌**，每桌 4 人
- **玩家只坐一桌**；其它桌由系统**模拟计算结果**（产出该桌淘汰名单 + 剩余筹码分布）
- 每桌跑一场仓库竞拍（§3）作为"一手"——即拍 1 个仓库
- 一手结束后：根据剩余筹码合并 / 重排桌位
- 决出**最后一名筹码持有者**为冠军

### 5.2 盲注递增（入场费阶梯）

- 每 **15 分钟** 提升一档**单品入场费（大盲注）**
- 共约 **9 档**，最终入场费 ≈ 初始的 **20×**
- 阶梯参考（首档 = 100 筹码）：

| 档位 | 时间 | 单品入场费 | 倍数 |
|---|---|---|---|
| 1 | 0:00 | 100 | 1× |
| 2 | 0:15 | 150 | 1.5× |
| 3 | 0:30 | 250 | 2.5× |
| 4 | 0:45 | 400 | 4× |
| 5 | 1:00 | 600 | 6× |
| 6 | 1:15 | 900 | 9× |
| 7 | 1:30 | 1300 | 13× |
| 8 | 1:45 | 1700 | 17× |
| 9 | 2:00+ | 2000 | 20× |

> 这个递增的"单品入场费"= §3.2 中**每件货品开拍前**扣的筹码量。它既是大盲注（强制成本），也是 re-buy/add-on 的**军资定价**（见 §5.3）。
>
> demo 阶段时长可压缩（例如 1 分钟/档），方便快速演示完整赛事；用配置项控制。

### 5.3 重购规则

| 概念 | 触发条件 | 价格 | 获得筹码 |
|---|---|---|---|
| **re-buy** | 自己筹码低于 *初始买入筹码* 的 **20%** | 当前档位入场费（军资） | 当前**全场剩余玩家平均筹码**量 |
| **add-on** | 自己筹码归零（被淘汰） | 当前档位入场费（军资） | 当前**全场剩余玩家平均筹码**量 |

- **次数无上限**，但**最后一档盲注期间禁止任何 re-buy / add-on**（决赛期不再接受新筹码注入）
- 重购的筹码量 = 全场（含其它桌）剩余玩家的筹码均值，**确保新加入者不会一进来就劣势/优势悬殊**

### 5.4 多桌模拟（demo 简化方案）

玩家所在桌：完整真实交互。

其它桌：每"手"结束时，按以下蒙特卡洛简化规则模拟：

```
对每张桌：
  1. 从该桌玩家筹码分布抽样
  2. 按 AI 性格权重决定本手赢家
  3. 按高斯分布给出筹码转移量
  4. 触发 re-buy/add-on 检查
  5. 输出该桌结果到锦标赛大事件流
```

玩家可在桌面顶部看到**赛事状态条**：剩余玩家数、自己的排名（按筹码量）、下一档盲注倒计时、总奖池。

### 5.5 奖励结构（demo 简化）

最后 4 名按比例瓜分总奖池（所有买入 + 重购的军资总和）：

| 名次 | 分成 |
|---|---|
| 1 | 50% |
| 2 | 25% |
| 3 | 15% |
| 4 | 10% |

## 6. AI 玩家设计

### 6.1 性格类型（核心实现 3 种，但 demo 已停用 aggressive）

| 类型 | 估价偏好 | 出价行为 | 押注行为 | demo 启用 |
|---|---|---|---|---|
| **保守派**（如荀彧） | 偏低 10% | 报价贴着自己估值，绝不超出 | 几乎不押，只在末轮信息充分时押 | ✓ |
| **激进派**（如吕布） | 偏高 5% | 第 1 轮就敢报高价博"一击成交" | 高频押，从早期就开始押 | ✗ 已停用 |
| **诈唬派**（如贾诩） | 估值准确 | 第 1~2 轮故意压低或报中价吸引对手追加；末轮突然加价 | 中频，倾向于晚押降低风险 | ✓ |

> **激进派为何停用**：自从 §4.4 把押注金固定为 `entryFee × 5` 后，激进派"R1 直接报估值 ×1.5~2.2"
> 总能压制其它玩家但又因高价不能押注（押注金常超 50% 筹码上限），结果中标但回收价 < 中标价 → **赢比赛但亏钱**。
> demo 桌固定为 1 人 + 3 AI（2 保守 + 1 诈唬），平衡度更佳。
> 激进派代码保留，单测仍验证其行为，仅 `playSession.ts` 不再分配此性格。

### 6.2 AI 决策流程

```
每轮:
  1. 估算仓库总值 = sum(各藏品估值) × (1 + 性格偏移) + 高斯噪声(σ 随轮次递减)
     单件藏品估值优先级（高 → 低）：
       a. 公共揭示（§3.6 'reveal-item'）→ 精确价值
       b. 自己技能揭示（品质+轮廓）   → 该稀有度中位价
       c. 自己技能揭示（仅品质）     → 该稀有度中位价
       d. 自己技能揭示（仅轮廓）     → 面积 × 全仓平均单格价
       e. 完全未知                  → 全仓平均期望
  2. 计算"心理上限" = 估值 * 风险系数(性格)
  3. 决定本轮报价：
     - 保守派：报 min(估值, 上轮所有报价中位数 + ε)
     - 激进派：第 1 轮直接报 估值 × 1.5~2.2，搏一击成交；之后跟随心理上限
     - 诈唬派：前期报"估值 × 0.6~0.8"故意诱导；末轮报 估值 × 1.0~1.1
  4. 决定押注：
     - 看本轮报价偏离自己估值是否在 ±10% 内（偏离越小越愿押）
     - 综合性格的"押注意愿"权重
```

> 公共信息进入 `state.publicReveals`，所有玩家共享这一精确知识。

### 6.3 武将与竞拍人技能

每位玩家在场前选定一名**武将**出战，每名武将**绑定固定竞拍人技能**——增强代入感，与皮肤化外观天然咬合。

#### v0.1 实现 3 名武将（其余作为 v0.2 扩展库）

| 武将 | 阵营 | 技能名 | 触发时机 | 效果 | 仅自己可见 |
|---|---|---|---|---|---|
| **诸葛亮** | 蜀 | 卧龙观气 | 每次出价后 | 揭示 **2 件**随机藏品的**品质**（左上格亮起色点，泄露品质 + 左上位置） | ✓ |
| **曹操** | 魏 | 望气定品 | 每次出价后 | 揭示 **2 件**随机藏品的**轮廓**（占位染色，泄露形状 + 完整位置但不知品质） | ✓ |
| **司马懿** | 魏 | 终极洞察 | 第 4 轮**开始时**（无需出价触发） | 一次性揭示**全部**藏品的品质和轮廓（不揭示具体名字与价值） | ✓ |

#### 技能机制要点

- **触发时机两类**：
  - "每次出价后"型（诸葛亮、曹操）→ 出价提交后立即触发，本仓最多触发 5 次（每轮 1 次，本仓未成交即继续）
  - "特定轮次"型（司马懿）→ 在指定轮次开始时触发一次
- **揭示对象随机抽取**：从本仓尚未被自己技能揭示过的藏品池中随机抽
  - 诸葛亮：抽 2 件揭品质
  - 曹操：抽 2 件揭轮廓
  - 注：同一藏品可能既被诸葛亮揭过品质，又被曹操揭过轮廓——视为该玩家对它"双重已知"，但其他人不知
- **可见性严格不对称**：技能产出的信息只对持有者可见（即便观战别的玩家也看不到他的"已知"）
- **揭示过的信息持续到本仓结束**：不会消失，玩家可在 UI 任意切换查看
- **AI 也使用相同技能**：AI 选定武将后按相同规则触发，并把已知信息纳入估值计算（§6.2）

#### 设计意图

- 信息不对称是博弈的核心：知道得越多越敢出高价，但你也要担心对手是否知道更多
- 司马懿的"突袭式终极洞察"创造一个**第 4 轮信息核爆**——之后只剩 1~2 轮可竞争
- 诸葛亮 vs 曹操构成"品质 vs 轮廓"两类策略：知道一件神话的品质 ≠ 知道一件 4×4 的占地

#### 平衡参数

- 揭示数量、触发频率均为 [§9 CONFIG](#9-配置项汇总便于调参) 中的可调参数
- demo 阶段三技能默认强度大致均衡；后续观察 AI 胜率再调

### 7.2 关键交互细节

- **报价**：滑块 + 数字输入双向同步；"过"按钮一键归零
- **报价快捷**（仅 R2~R4 显示，R5 阈值=1.0 无意义所以隐藏）：
  - **上轮出价 X**：一键填入"我上一轮的报价金额"，方便保持
  - **× T**（T = 当前轮成交阈值，R2=1.6 / R3=1.3 / R4=1.1）：把当前输入框值 ×T，等价于"刚好卡住本轮成交阈值"。若输入框为 0，则按"上轮出价 × T"自动填
- **押注**：复选框「押 ±10%（猜本轮报价 ±10% 含真实总值）」**金额不可变**，固定 = 5× 入场费 ・ UI 中括号注明规则
- **bid strip（玩家行内）**：每名玩家旁边显示其所有已揭露的轮次报价（R1=…/R2=…/…）
  - 1st 报价格子加金色高亮 + 微辉光
  - 最新一轮的格子带 `revealBid` 动画（错峰 280ms 揭示，从顶部玩家开始）
  - **中标 cell**：成交那一轮的中标者格子获 `winning-bid` 类（金色脉动光晕 + 👑 角标）
- **公共信息 banner**：蓝色描边盒子，进入新轮时带 `pulseInfo` 脉冲动画（1s）
- **成交过渡**（关键）：拍卖结束时**先停留在 auction 屏**展示末轮全员明码（含中标 cell 高亮），把"出价控件"区域换成"🏆 X 以 Y 中标 / 查看完整结算"按钮。点按钮后才切到 settlement 屏。**目的**：给玩家时间消化最后揭露的报价。
- **结算屏顶部**：醒目的"🏆 中标者 + 中标价 + 净利润"横幅；下方再展示传统数字面板与表格
- **图鉴（codex）**：右上角 "📖 藏品图鉴" 按钮 → 弹出 modal，列全部 ~46 件藏品原型
  - 卡片按 **价值降序**（最重要信息），显示稀有度色边框 + 图标 + 名 + 类别 + 价值（含价值带范围）
  - **每张卡按实际格数显示**：用 12 列 × 56px 的 CSS Grid + `grid-auto-flow: dense`，每张卡 `grid-column: span W; grid-row: span H;`（用第一个 preferredShape）
    - 4×4 神话级（如传国玉玺）= 一张大卡占 16 格
    - 1×6 / 6×1 长卷型（如七星宝刀）= 细长卡（名字竖排）
    - 1×1 微件（残简、银钱等）= 仅显图标 + 价值
    - dense 算法把小件填补大件留下的空隙，俄罗斯方块式紧凑布局
  - 内容详细程度按面积自动调整：tiny (1 格) 仅图标+价值；中件加名字；大件加类别+价值范围
  - 点击仓库视图中**部分揭示**的藏品自动打开过滤后的图鉴：
    - 仅品质已知 → 过滤为同稀有度
    - 仅轮廓已知 → 过滤为同形状（任一 preferredShape 匹配）
    - 双知 → 过滤为同稀有度 + 同形状
    - 公共揭示 → 仅显示该具体藏品，且**用本仓实际生成值**覆盖原型 baseValue（修 v0.1 的 "图鉴 120 但公共信息 119" 不一致 bug）
  - 卡片价值标签自适应：图鉴默认显示 baseValue + "典型 ±15%"；从公共揭示打开时显示 actualValue + "本仓实际"
- **结算屏**：传统数字面板 + 玩家筹码变动表 + 押注结算表 + 完整日志 + "再来一仓 / 重选武将"

### M11 多桌模拟简化算法

为不引入完整影桌拍卖循环（开销大），影桌用**简单蒙特卡洛**：

```
每当玩家桌进入下一手时，对每张影桌：
  1. totalChips -= entryFee × alive            （入场费沉没）
  2. avg = totalChips / alive
  3. elimProb = clamp(entryFee × 6 / avg, 0, 0.55)
  4. if rand() < elimProb: alive -= 1          （随机淘汰一人）
  5. if alive ≤ 1: 该桌冻结，不再推进
```

设计权衡：
- 不模拟具体藏品拍卖（只用聚合统计），性能 < 1ms/手
- elimProb 公式让"avg ≈ 6× entryFee"时约 55% 出局，"avg > 30× entryFee"时几乎不出局——与真实 MTT 节奏吻合
- 顶栏 `全场存活 X/64` 体现紧张感；`我桌 N` 副标签让玩家知道自己桌情况
- 玩家被淘汰即结束（不模拟到 1 人），名次 = 当时全场存活数 + 1

| 玩家初始筹码 | **24000** | = MTT 起始筹码 ×24，让玩家能压过较高仓位（仓库总值范围 ~3000~9000）|
| 玩家入场费 | **100** | 与 MTT 第 1 档盲注一致 |
| 玩家组成 | 1 人 + 3 AI（性格固定 激进 / 诈唬 / 保守）| AI 武将分配：玩家选其一 → AI 用其余 2 名 + 1 名玩家武将的"影武者" |
| AI 思考延迟 | **300ms** | 提交后给 UI 揭露动画一点呼吸节奏 |
| 揭露动画错峰 | **280ms / 玩家** | 顶部玩家先揭，向下逐次 |

## 11. 待定 / 后续讨论

### v0.1 范围内待补
- [ ] **顶部密集排布算法**：是用启发式（按面积降序，从上往下扫描第一可放位）还是更精细的回溯填充？需要在 M1 里定
- [ ] **同一藏品被两人技能各自揭过怎么处理**：双方各自看到自己的视图，对方不可见——确认 OK，但 UI 上要不要有"对手已侦察"的暗示？
- [ ] **司马懿"全揭示"是否包含具体名字与价值**：当前设计只揭品质+轮廓，不含名字与价值。若未来想做"特级技能"可揭名字
- [ ] **AI 选将策略**：开局随机选 / AI 强度等级决定 / 玩家不可选已被 AI 选过的
- [ ] **拍品库容量**：30~60 件/仓 × N 仓的 MTT 全程，需要一个稳定能产出多样仓库的拍品资料库。建议 v0.1 至少 60 件原型

### v0.2 及之后
- [ ] 更多武将与技能（典韦：揭某行；黄月英：揭某区域；周瑜：揭对手某次出价偏离自己估值的方向；等）
- [ ] 道具/被动效果（"持有传国玉玺：场末额外 +5% 回收"等）
- [ ] AI 诈唬派策略上限调优（避免戏剧性失真）
- [ ] 联网模式的房间/匹配/同步策略
- [ ] 经济曲线调优（是否会出现"AI 永远赢"等极端情况）
