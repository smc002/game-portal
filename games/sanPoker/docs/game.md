# sanPoker：核心规则设计文档

> sanPoker 是一款以《三国：谋定天下》战斗系统为底层的**双人对战 + 下注博弈**游戏。
> 核心玩法融合了 MTG 传包轮抽、德扑信息渐进揭示、三谋武将战法战斗三套成熟机制。
> 战斗规则详见 `battle_reference.md`。

---

## 一、设计定位

| 维度 | 设计选择 |
|------|----------|
| 游戏模式 | 双人 PVP 对局，单局 2–4 分钟 |
| 核心循环 | 发牌 → 轮抽 → 下注 → 战场条件 → 构筑 → 下注 → 决战 |
| 信息结构 | 渐进揭示（类似德扑 preflop → turn → river） |
| 博弈类型 | 不完全信息 + 双盲下注 + 心理博弈 |
| 最终目标 | 扩展为锦标赛模式（MTT），剔除深码对短码的压制机制（见第八节） |
| 合规风控 | 虚拟筹码、积分/通行证奖励，避免真金对赌题材 |

## 二、单局对决流程（核心玩法）

### 流程总览

```
[Phase 0] 开局揭示 3 个候选战场条件
              ↓
[Phase 1] 发公共武将 + 各发 3 张手牌   ──▶ 【Bet 1】双盲下注
              ↓
[Phase 2] 各选 1 张留下，传 2 张给对手   ──▶ 【Bet 2】双盲下注
              ↓
[Phase 3] 从 3 个候选条件中随机选 1 生效（条件公开）
              ↓
[Phase 4] 从 4 张牌中选 3 张构筑阵容 + 选阵型（密封）  ──▶ 【Bet 3】双盲下注
              ↓
[Phase 5] 公布最终阵容 → 战斗推演 → 结算筹码
```

---

### Phase 0：战场条件揭示

- 系统从**全量条件池（30 条）**中随机抽出 **3 张战场条件卡**
- 3 张条件**公开展示**，双方可见
- 它们是"本局战场可能出现的 3 种环境"——**最终会从中随机触发 1 条**
- 此阶段玩家还未看到任何手牌，是"上帝视角"下的环境预判

### Phase 1：发牌

- 发放 **1 张公共武将**（双方共用候选）
- 各自发放 **3 张手牌**（每张 = 1 武将 + 携带的 2 个战法）
- 公共武将对双方可见；手牌仅自己可见

**🎲 Bet 1**：双盲下注（详见第三节）

### Phase 2：传包轮抽

- 双方**同时密封操作**：
  - 从自己 3 张手牌中选 1 张**留下**（置于待构筑区）
  - 剩余 2 张**传给对手**
- 操作完成后公开传牌结果：
  - A 手上：A 自己留的 1 张 + B 传过来的 2 张 = 3 张候选
  - B 手上：B 自己留的 1 张 + A 传过来的 2 张 = 3 张候选
- 加上公共武将，每人手上共有 **4 张候选卡**

**🎲 Bet 2**：双盲下注

### Phase 3：战场条件抽选

- 从 Phase 0 揭示的 3 张候选条件中**随机抽 1 张生效**
- 公开揭示，本局战场规则敲定
- 未被选中的 2 张丢弃，本局失效

> **此时信息状态**：阵容结构仍有隐藏（最终 3 张谁进阵容未定），但战场环境已定。

### Phase 4：最终构筑

- 双方**同时密封操作**：
  - 从自己的 4 张候选（1 留 + 2 收 + 1 公共）中选 **3 张进入阵容**
  - 决定 3 个位置：前锋 / 中军 / 大营
- 丢弃的 1 张牌**不公开**（对手不知道你舍弃了哪张，这是阵容诈唬空间）

**🎲 Bet 3**：双盲下注

### Phase 5：决战

- 双方同时**公开阵容与阵型**
- 结合生效的战场条件，按战斗引擎推演 8 回合战斗（详见 `battle_reference.md`）
- 胜方获得**本局总奖池**；败方损失已下注筹码

## 三、下注机制

### 双盲倍数下注

每次下注，玩家**从三个乘数中密封选择**一个：

| 选项 | 乘数 | 语义 |
|------|------|------|
| 保守 | **×1** | 按基础注，观望 |
| 试探 | **×2** | 适度施压 |
| 加注 | **×3** | 强信心/诈唬 |

### 本轮下注金额计算

双方同时揭示乘数后：

```
本轮下注金额（每方）= 本轮基础注 × 我方乘数 × 对方乘数
```

**示例**（假设基础注 = 10 筹码）：

| 我方 | 对方 | 每方实付 | 本轮奖池 |
|------|------|----------|----------|
| ×1 | ×1 | 10 | 20 |
| ×1 | ×3 | 30 | 60 |
| ×3 | ×3 | 90 | 180 |

### 乘数机制的特性

1. **双方总是支付相同金额**（对称）：乘数乘积相同，无先后手优势
2. **下限由较小乘数决定**：任一方选 ×1，则双方都只付 ×1 × opp_m
3. **激进需对方配合**：想把池子做大，对手也得愿意加注
4. **天然产生博弈**：
   - 强势方希望对方跟 ×3（但对方若察觉劣势会 ×1 止损）
   - 弱势方选 ×1 想保护筹码（但对方若判断自己更强就会 ×3 压榨）
   - 选择的"同步性"本身就是心理博弈

### 基础注（Base）

- Bet 1 基础注 = **10 筹码**
- Bet 2 基础注 = **20 筹码**（翻倍）
- Bet 3 基础注 = **40 筹码**（再翻倍）

越靠后信息越充分，基础注越大，戏剧性递增。

### 单局筹码上限

单局总支出上限 ≈ `10×9 + 20×9 + 40×9 = 630` 筹码（两人都 ×3 的极端情况）
起始筹码建议 **2000**（约可参与 3 次满级 all-in 对局）。

### 本局总奖池

```
总奖池 = 2 × (Bet1 每方实付 + Bet2 每方实付 + Bet3 每方实付)
```

胜方获取全部奖池；平局按兵力比例分配。

### ⚠️ MVP 暂不实装"投降/弃牌"

原设计中有"chicken out / fold"行动。当前简化版下注系统中，**一旦开局即锁定**，只能通过"×1 + ×1 = ×1"组合把三轮损失控制在最低（10+20+40=70 筹码）。

> 后续若发现"无投降"的心理博弈空间不足（尤其是面对明显败局时），可在 Bet 2 / Bet 3 增加"弃牌"选项（输掉本轮已付注，立即结算）。

## 四、战场条件池

### 条件池设计原则

1. **胜率偏移限制在 ±10%~15%**（避免一条件定胜负）
2. **按三类分桶抽取**：每局 3 条各来自不同类别
3. **MVP 全量池 30 条，每赛季轮换 1/3**

### 类别 A：阵营/兵种（不对称，取决于双方阵容构成）

| 条件 | 效果 |
|------|------|
| 魏风盛行 | 魏国武将武力 +10% |
| 蜀韵悠长 | 蜀国武将统率 +10% |
| 吴水绕江 | 吴国武将先攻 +8% |
| 群雄逐鹿 | 群势力武将兵力 +10% |
| 骑兵突袭 | 骑兵武将武力 +12% |
| 弓兵射程 | 弓兵武将智力 +12% |
| 枪兵列阵 | 枪兵武将统率 +12% |
| 盾兵死守 | 盾兵武将兵力 +15% |
| 同营增益 | 全队同阵营时额外 +5% 全属性 |
| 多兵种 | 全队不同兵种时额外 +3% 全属性 |

### 类别 B：机制调整（对称，改变战斗底层规则）

| 条件 | 效果 |
|------|------|
| 速战速决 | 战斗回合上限 8 → 6 |
| 持久战 | 战斗回合上限 8 → 10 |
| 风云涌动 | 所有主动战法发动率 +15% |
| 决心不灭 | 所有主动战法发动率 -10% |
| 战意高昂 | 所有暴击率 +12% |
| 沉着应战 | 所有暴击率 -8% |
| 破势压阵 | 指挥战法效果 ×1.2 |
| 风起云涌 | 被动战法触发率 +20% |
| 先声夺人 | 首回合所有伤害 +30% |
| 后发制人 | 第 5 回合后所有伤害 +20% |

### 类别 C：环境增益（对称，偏向某流派）

| 条件 | 效果 |
|------|------|
| 烈日焚城 | 灼烧伤害翻倍 |
| 毒雾弥漫 | 中毒伤害翻倍 |
| 狂风助势 | 追击战法伤害 +25% |
| 地动山摇 | 所有控制类负面状态持续 +1 回合 |
| 医营庇护 | 所有治疗效果 +30% |
| 禁咒罩场 | 所有治疗效果 -50% |
| 先攻加成 | 全体先攻 +15 |
| 先攻削弱 | 全体先攻 -10 |
| 单体强化 | 单体战法伤害 +20% |
| 群体压制 | 群体战法伤害 +15% |

### 抽取规则

每局抽 3 条时：
- 1 条来自类别 A
- 1 条来自类别 B
- 1 条来自类别 C

确保每场都有"阵营博弈 + 规则博弈 + 流派博弈"三个维度。

## 七、单局筹码流示例

假设起始筹码各 2000，基础注 10/20/40：

```
Bet 1：A 选 ×2，B 选 ×1  → 每方付 20，池中 40
        A 剩 1980，B 剩 1980

Bet 2：A 选 ×3，B 选 ×2  → 每方付 120，池中累计 280
        A 剩 1860，B 剩 1860

Bet 3：A 选 ×3，B 选 ×3  → 每方付 360，池中累计 1000
        A 剩 1500，B 剩 1500

决战 → A 胜
A 最终：1500 + 1000 = 2500
B 最终：1500
```

## 八、锦标赛（MTT）扩展——待设计

### 基本结构（参考德扑 MTT）

- 所有玩家统一 buy-in，等额起始筹码
- 筹码归零 → 淘汰
- 基础注按时间轴递增（类似盲注级别）
- 自动匹配 / 桌次合并
- 最后 8 人进 Final Table，奖金阶梯分配

### ⚠️ 关键设计问题：深码对短码的压制缺失

**德扑 MTT 中，深码压制短码的机制**：
1. 深码可以 all-in 逼短码 all-in（因为短码只要一次损失就出局）
2. 深码能吸收多次小损失，短码不能
3. 短码面对深码加注时，只能 "fold or commit"，没有中间选项

**sanPoker 当前 ×1/×2/×3 乘法机制下的问题**：
- 因为"任一方 ×1 则双方都只付 ×1 × opp"，**短码玩家可以无限选 ×1 压低总支出**
- 深码想"做大池子逼短码"，短码选 ×1 即可把深码 ×3 的威胁降到 ×3（而非 ×9）
- 这让深码的"下注威慑力"被结构性削弱

### 待讨论方向（下一轮对话聚焦）

A. **改"乘法"为"最大值"**：双方支付 = `max(我, 对方) × base`，高者主导池子
B. **加入 all-in 按钮**：作为第 4 个选项，强制对方 fold 或全部跟进
C. **引入"保险费"**：筹码量大者每轮需额外支付 1%~2% 的保有成本
D. **强制基础注递增**：每 N 分钟基础注翻倍，短码不能无限龟缩
E. **"被覆盖"规则**：深码 ×3 时，若短码筹码不足 ×3 则自动转为 all-in，失败直接出局
F. **按筹码差设调整**：双方筹码差 > 2 倍时，深码方可额外选 ×5 选项（短码无此权）

这些方向需要在下一轮详细权衡。

## 九、开发阶段路线

### 阶段 1（MVP）：单局对战闭环

- [ ] 战斗引擎（参考 `battle_reference.md`）
- [ ] 3 武将 × 2 战法样本池跑通战斗

- [ ] 扩展武将池至 15~20 位
